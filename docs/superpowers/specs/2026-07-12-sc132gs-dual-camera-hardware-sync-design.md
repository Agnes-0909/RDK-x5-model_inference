# SC132GS 双摄硬件同步曝光设计

## 目标

让 `mipi_vse_bpu_zerocopy` 的左右两颗 SC132GS 以 30 FPS 持续、同相位硬件触发曝光。MIPI → ISP → VSE → BPU 的现有双路流水线保持异步运行，不等待一帧推理和后处理结束后再触发下一帧。

“同步”指两颗传感器由硬件触发进入曝光，而不是主线程先后获取两张图后进行软件配对。

## 现状与约束

- 当前传感器工作在 `NORMAL_M`，VIN 的 LPWM 被禁用，因此两颗传感器自由运行，不能保证同一曝光时刻。
- 当前传感器文件名标注 30 FPS，但 `SENSOR_FPS` 实际为 60，必须统一为 30 FPS 后再配置触发周期。
- X5 SDK 的 SC132GS 驱动支持 `SLAVE_M`，官方样例也提供 LPWM 触发配置。
- 板级设备树为两个相机接口提供不同 LPWM 通道。软件将按设备树路由通道，不能硬编码单一连接器。
- 两个 LPWM 通道是否共享相位，以及 GS130W 是否把触发线接至两颗传感器，必须在开发板上验证；这不是软件静态检查能够证明的。

## 方案

采用 X5 VIN LPWM 双通道同参数触发：

1. 将两颗 SC132GS 的 camera sensor mode 切换到 `SLAVE_M`。
2. ISP 保持 `ISP_NORMAL_M`；`SLAVE_M` 仅用于传感器外部触发模式，不能误配为 ISP/HDR 模式。
3. 启用 VIN `lpwm_attr`，由每路设备树路由选择 LPWM 通道。
4. 两路使用相同触发参数：周期 33333 微秒、相同 offset、相同 duty time 和 trigger mode。
5. 先完成左右两路全部节点、flow 和触发参数配置，再启动两路 flow，减少启动阶段的非确定性。
6. 保留现有左右独立推理线程。采集和推理继续流水执行，不引入逐帧处理屏障。

## 软件结构

### 传感器静态配置

`src/sensor/sc132gs_linear_1088x1280_raw10_30fps_1lane.c` 负责声明 SC132GS 的 30 FPS slave 工作模式和 LPWM 基准参数。所有与帧率关联的 camera、MIPI 和触发周期参数保持一致。

### 运行时路由

`src/vio_pipeline.cpp` 克隆静态配置后，读取相机接口的设备树 `lpwm_chn`，将该通道应用到本路 VIN LPWM 配置。运行时不得再次无条件关闭 LPWM。

### 双路启动

左右 pipeline 的配置阶段和启动阶段应保持清晰边界。若现有 API 无法做到一次调用配置两路后统一启动，则采用最小启动间隔，并以硬件时间戳实测结果判断是否满足同步；不能把“连续调用 start”当作同曝光的证明。

### 时间戳与日志

采集路径记录每路 frame id 和硬件时间戳。协调层按帧序或最近时间戳计算左右差值，周期性输出同步统计，至少包括当前差值和观察到的最大绝对差值。时间戳异常或帧序跳变记录告警，但不阻塞实时流水。

## 异常处理

- 设备树缺失 LPWM 路由：初始化失败并打印具体 host 和缺失属性，禁止静默退回自由运行。
- sensor slave 初始化或 LPWM 配置失败：停止并回收已创建的 VIO 资源。
- 左右时间戳持续超出验收阈值：打印同步告警，提示检查 LPWM 相位和模组触发线；不伪报为同步成功。
- 单路丢帧：记录 frame id/时间戳不连续，后续帧继续处理。

## 验证与验收

### 静态与构建验证

- 增加配置级测试，确认 30 FPS、`SLAVE_M`、LPWM enabled，且运行时不再覆盖为 disabled。
- 在 X5 SDK Docker 交叉编译环境中完整构建工程。
- 保持现有零拷贝检查和其他测试通过。

### 板端验证

1. 在 X5 开发板启动双路采集，检查两路都能稳定输出、推理。
2. 采集一段时间戳日志，计算左右同序帧时间差及最大抖动。
3. 使用同时照射两颗传感器的快速闪光或示波器测量 FSIN/曝光信号，确认不存在一帧级错位。
4. 若两个独立 LPWM 通道存在固定相位差且不能共同复位，则将一个硬件触发信号扇出至两颗传感器，软件仍维持 slave 配置。

验收标准是两路持续采集、无新增错误，并由硬件时间戳和闪光/示波器测试证明同步；仅凭左右 `getframe` 调用顺序不能验收。

## 非目标

- 不实现“推理全部结束后才触发下一次曝光”的单步采集模式。
- 不改变 MIPI → ISP → VSE → BPU 零拷贝链路。
- 不重构现有推理、后处理或结果可视化功能。
